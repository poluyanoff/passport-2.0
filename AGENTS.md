# Паспорт дизайн-задачи

Перед работой прочитай `README.md`, `docs/PRODUCT.md`, `docs/ARCHITECTURE.md` и `docs/OPERATIONS.md`.

## Правила разработки

- Работай в React-экранах из `screens/`; точка входа формы — `screens/main.js`.
- Используй `React.createElement` и компоненты `T` из `screens/runtime.js`.
- Не копируй бандлы, не редактируй `node_modules` и не заменяй компоненты Taiga UI собственными аналогами.
- Для цветов и типографики используй токены и классы дизайн-системы. Пользовательские CSS-правила допустимы только для раскладки и композиции.
- Не выводи секреты в код, консоль, документацию или браузер. `.env` и `.dev.vars` не коммитятся.
- Сохраняй контракт `POST /api/review`: при изменении payload обновляй frontend, Node API, Worker и правила одновременно.

## Проверка перед сдачей

```sh
npm run review:check
npm run build
```

При UI-изменениях дополнительно открой приложение и проверь `window.TaigaUI.check({ log: false })`: результат должен быть пустым массивом.

## Публикация

`main` автоматически разворачивается в Cloudflare через GitHub Actions. Не выполняй ручной production-деплой, если пользователь прямо не попросил об этом.
