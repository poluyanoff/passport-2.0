# Контекст продукта для Codex

## Что это

«Паспорт дизайн-задачи» — сервис, который превращает описание продуктовой задачи пользователя в структурированный паспорт для передачи дизайнеру и форматированное описание для эпика.

Пользователь работает со своим паспортом самостоятельно. Совместного редактирования одного паспорта, аккаунтов, логина и базы данных сейчас нет.

## Главный пользовательский путь

1. Пользователь заполняет восемь шагов: аудитория, ситуация, данные, влияние на бизнес, гипотезы, метрики, аналоги, дата результата. Гипотезы необязательны, их можно добавлять, редактировать и удалять — максимум десять.
2. Интерфейс проверяет обязательные данные непосредственно в форме или toast'ом.
3. Перед финальным экраном приложение запускает содержательную AI-проверку.
4. Пользователь получает список замечаний с переходом на нужный шаг, вносит правки и возвращается к результатам.
5. После успешного завершения пользователь копирует описание для эпика: в буфер передаются HTML для форматирования в Jira и обычный текст для совместимости.

## Принципы продукта

- Не додумывать бизнес-факты и не требовать ссылки, примеры или аналоги как обязательные поля.
- Подсказывать конкретно и исправимо; AI-рекомендации не должны дублировать формальную валидацию формы.
- Использовать Taiga UI Proprietary и её токены/иконки вместо самодельных аналогов компонентов.
- Интерфейс — только форма: внешняя демонстрационная обёртка и индикатор DS скрыты.
- На длинных шагах основное действие находится в sticky-footer.

## Границы текущей версии

- Паспорт не сохраняется между сессиями и не попадает в базу данных.
- AI-проверка доступна через OpenAI на сервере; если провайдер недоступен или нет баланса, пользователь получает fallback локальных правил и понятный toast.
- Сервис доступен многим людям одновременно, но данные одного пользователя не видны другому.

## Технические решения, которые нельзя нарушать без отдельного решения

- Ключ OpenAI остаётся только на сервере/в Cloudflare secret, никогда не отправляется в браузер и не коммитится.
- Production публикуется только через пуш в `main` и GitHub Actions.
- `main` должен оставаться собираемым: перед пушем запускать `npm run review:check` и `npm run build`.
- Любое изменение структуры данных паспорта согласовывать одновременно в `screens/main.js`, правилах, Node API и Worker API. Метрики добавляются, редактируются и удаляются через модальное окно; каждая включает название, текущее и целевое значения, единицу измерения и необязательную дату текущего значения.

## Ближайшее развитие

Переход от прототипа к рабочему сервису: повысить качество AI-проверки по пользовательским правилам, затем при необходимости добавить хранение паспортов. Не добавлять логин, совместное редактирование или БД без явного запроса.
